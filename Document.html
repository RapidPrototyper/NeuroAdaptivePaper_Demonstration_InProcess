1. System Overview

This is a complete web‑based implementation of the neuroadaptive cursor control paradigm described in Zander et al. (2016). It simulates a BCI where a robot (cursor) learns to move toward a target based on user's brain activity patterns, with movements classified and recorded for offline EEG analysis.

🎯 Purpose: Demonstrate how a cursor can learn implicit direction preferences using EEG‑like feedback. The system sends detailed event markers via LSL for synchronization with real or simulated EEG data.

Key components:

  • Frontend (HTML/CSS/JS): Configuration UI, Three.js 3D visualization, movement pipeline, machine learning model, live preview, and LSL marker generation.
  • Backend (Python): WebSocket server that receives markers and forwards them to a single LSL stream (NeuroCursor_Markers).
  • Communication: WebSocket (ws://localhost:8765) between browser and Python, LSL protocol to recording software.

3. HTML Layer (index.html) – Comments & Structure

The HTML file defines the entire user interface. Below is a commented breakdown of its major sections.

3.1 Intro Screen (#intro-screen)

Contains the experiment description, controls summary, and all configuration panels. It is visible only before the experiment starts.

  • Experiment Information: Explains the three phases and what the user needs to do.
  • Visual Settings Panel: All customisation options – grid size, style, cursor/goal/camera modes, timing (in seconds), marker toggles.
  • Start Button: Triggers startExperiment().
  • Profile Management: Save/load/delete profiles, export/import as JSON, built‑in “Original Paradigm” profile.
  • Sequence Runner: Build a queue of profiles and run them back‑to‑back automatically.

3.2 HUD Panels

These are hidden initially and can be toggled with the H key.

  • #stats-panel: Shows current phase, targets, jumps, moves, grid size, and positions.
  • #controls-panel: Indicates whether the user needs to press keys (Manual phase) or just observe.
  • #model-panel: Displays a bar chart of direction probabilities and a grid of values.
  • #event-markers-panel: Scrollable text area of all LSL markers sent.
  • #author-badge: Shows LSL connection status.

3.3 Gray Square Indicator (#gray-square)

Located in the bottom‑left corner. Its colour changes to reflect the current phase:

  • ⬛ Black + Border Intro screen
  • ⬜ Medium Gray Calibration
  • ⬜ Light Gray BCI
  • ⬛ Dark Gray Manual
  • ⬛ Black Break
  • 💫 Flashing White During movement (via a separate overlay)

4. CSS Layer (styles.css) – Visual Design

The CSS file provides a dark theme with a blue accent (#63b3ed). It styles all panels, buttons, and the live preview container. Key features:

  • Design section enhancements: Glass‑morphism, subtle borders, and hover effects for control groups.
  • Live preview container: Sticky positioning with a polished border and hover glow.
  • Responsive layout: Adjusts for mobile/tablet using media queries.
  • Animations: Pulse borders for active controls, slide‑in feedback, and a green pulse for LSL connection.
  • Gray square states: Different background colours for each phase, defined via CSS classes.

6. Python LSL Bridge (lsl_bridge.py)

This standalone WebSocket server forwards markers to LSL.

Class: LSLBridge

  • __init__(): Calls setup_lsl_stream() to create the LSL outlet.
  • setup_lsl_stream(): Creates a StreamInfo with name NeuroCursor_Markers, type Markers, one string channel. Adds metadata describing marker types and classification values.
  • send_to_lsl(marker_type, marker_value, jump_number): Formats the marker (e.g., adds cls1: prefix for cls1) and pushes it to the LSL outlet.
  • handle_client(websocket, path): Asynchronous coroutine that listens for WebSocket messages, parses JSON, extracts label, cls1, cls2, classifyNow, button, event, and calls send_to_lsl() for each present field.

Marker Formatting:

  • label → sent as‑is (no prefix).
  • cls1 → f"cls1:{value}"
  • cls2 → f"cls2:{value}"
  • classifyNow → f"classifyNow:{value}"
  • button → str(value) (e.g., "50001")
  • event → f"event:{value}"

7. Core Algorithms – Movement, Classification, Learning

Movement Selection

  • Calibration phase: Random direction among valid neighbours.
  • BCI & Manual phases: Weighted random selection based on userModel probabilities (higher probability → more likely to choose that direction). The model is initialised uniformly and updated only during the manual phase.

Angle & Classification

angle = calculateAngleToGoal(from, to);  // 0° = moving directly toward target, 180° = directly away.
cls1:  angle < 45  → 'toward'
       45 ≤ angle ≤ 100 → 'sideways'
       angle > 100 → 'away'
cls2:  angle < 1    → 'very good'
       1 ≤ angle ≤ 135 → 'neutral'
       angle > 135 → 'very bad'

These classifications are sent as separate markers to allow offline EEG analysis to correlate brain activity with both the direction and the quality of the movement.

User Model Update (Manual Phase)

When the user presses V (acceptable) or B (not acceptable) after a movement:

  • V: Increase probability of the chosen direction by learning rate (0.25); decrease the opposite direction.
  • B: Decrease chosen direction; increase perpendicular directions slightly.
  • Probabilities are re‑normalised to sum to 1.

This simulates how a BCI could learn the user's implicit preferences.

10. Troubleshooting

  • LSL Bridge not connecting: Ensure Python server is running (python lsl_bridge.py). Check if port 8765 is free.
  • Robot not loading: GLTF model may take time to fetch; fallback to a 3D sphere if loading fails.
  • No markers in LabRecorder: Verify markerPushing is ON (checkbox in settings). Also check that LSL stream name matches.
  • Timing too fast/slow: Adjust values in seconds; they are clamped to 100ms minimum.
  • Custom grid not moving: Grid must be at least 2×2 to have valid moves.
